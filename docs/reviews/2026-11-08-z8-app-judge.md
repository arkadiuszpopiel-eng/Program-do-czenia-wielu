# Z.8 — integracja modelu-sędziego (2026-11-08)

Karta: [#19](https://github.com/arkadiuszpopiel-eng/Program-do-czenia-wielu/issues/19).
Podstawa: `62925ed0`, wersja 0.0.85, gałąź robocza `test/z8-app-judge`.
Środowisko: chmura, Linux x86_64, Rust 1.94.1. Autor: Codex.

## Wynik

Dodano osiem testów integracyjnych `app-judge` (16 wariantów) i jeden test jednostkowy regresji.
Testy uruchamiają produkcyjne `app_judge::spawn`, kontekst historii, Router, `ModelJudge`,
`JudgeDriver`, `BrokerEngine` i `NoteLog`. Atrapy zastępują dostawcę modelu, historię sesji,
port procesów, zegar Brokera i zapis Audytu. Zegar Tokio jest wirtualny.
Testy nie wykonują połączeń z dostawcami API ani operacji na komputerze właściciela.

**Z.8 pozostaje w toku:** nie uruchomiono Windows/WebView2 ani prawdziwego modelu lokalnego.
Nie zmieniono progów, zestawów `evals/`, polityk Brokera ani macierzy akceptacji sprzętowej.
Etap nie jest zamknięty, więc numer wersji pozostaje 0.0.85.

## Znalezisko i poprawka

`context_from_turns` szukało od końca pierwszej odpowiedzi z informacją o dostawcy (`find_map`).
Gdy najnowsza odpowiedź nie miała `usage`, starsza odpowiedź chmurowa ustalała `local_only = false`.
Przy fakcie narzędzia `model_location = Cloud` hybrydowy sędzia dostawał zapis rozmowy, mimo że
pochodzenie najnowszej odpowiedzi było nieznane. Test integracyjny potwierdził żądanie do atrapy
dostawcy chmurowego; nie był to pomiar rzeczywistej wysyłki do API.

Teraz sprawdzana jest wyłącznie najnowsza odpowiedź. Brak informacji w tej turze oznacza
`local_only = true`: sędzia lokalny albo decyzja właściciela. Starsza tura nie może tego zmienić.

Przed poprawką czerwone były oba nowe testy:

- `unknown_latest_assistant_does_not_inherit_cloud_permission` — test kontekstu;
- `unknown_latest_origin_never_sends_history_to_cloud` — cała ścieżka z Routerem i Brokerem.

Po poprawce oba są zielone. Pozostałe scenariusze sprawdzają:

- zgodę jednorazową z działającym tokenem, zapisem Audytu i wpisem osi czasu;
- sześć kombinacji pochodzenia historii i faktów narzędzia — chmura tylko przy dwóch jawnych wskazaniach;
- zły JSON, błąd HTTP i brak odpowiedzi — karta właściciela;
- pusty Router lokalny i awarię lokalną — brak przejścia na Router hybrydowy;
- sędziego lokalnego dla przebiegu chmurowego, gdy nie ma Routera hybrydowego;
- granicę właściciela — zapora zamienia zgodę modelu w przekazanie decyzji właścicielowi;
- obniżenie trybu podczas oceny — Broker odrzuca spóźnioną zgodę, a dziennik zapisuje odrzucenie.
