ADR 0019 — Protokół klient–host niezależny od transportu

PoleWartość
StatusProponowany — czeka na podpis właściciela
Data2026-10-09
Powiązaneplan v6: docs/plan/02-architektura-docelowa.md (szew 3), 09-dostep-zdalny-i-bezpieczenstwo.md (uprawnienia klientów, R10), 03-roadmapa.md (B.1–B.3, B.5, D.1, D.6); ADR 0013, 0020, 0021
Zmieniawykonuje ADR 0013 (typy TS generowane z Rust zamiast pisanych ręcznie); nie zmienia listy poleceń ani zdarzeń

Kontekst

Dziś jest 210 poleceń w jednej liście (app-api/src/commands.rs, makro with_commands!), ok. 38 zdarzeń (AlfaEvent) i DTO w app-api/src/dto/. Interfejs zna tylko AlfaClient z dwiema implementacjami: TauriAlfaClient i FakeAlfaClient. To dobry punkt wyjścia, ale plan v6 zakłada trzy klienty (okno Tauri, panel WWW, Android) i trzy transporty (Tauri IPC, kanał szyfrowany, atrapa w testach). Brakuje pięciu rzeczy: numerów sekwencji zdarzeń (klient, który nie nadąża, po cichu gubi paczki w pump.rs), błędów strukturalnych (powłoka spłaszcza AppError do tekstu), tożsamości klienta i uprawnień (jedyne ACL to uprawnienia okien Tauri), oznaczenia poleceń zakładających lokalną maszynę oraz generowanych typów TS.

ElementPropozycja

Wersja protokołunegocjowana przy połączeniu; host obsługuje bieżącą i poprzednią, żeby telefon z nieaktualną aplikacją nadal działał; host może wymusić minimalną (R10)

Wznowienieklient po przerwie wysyła events_resume { after_seq }; gdy bufor nie sięga tak daleko, host odpowiada resync i klient czyta stan od nowa
Błędyprzez łącze idzie { code, message, details }; tekst dla użytkownika tłumaczy klient (i18n PL/EN)

Typy TSgenerowane z Rust (ADR 0013); CI sprawdza git diff --exit-code; ręczne types*.ts znikają
Transportyte same ramki przez Tauri IPC, przez kanał szyfrowany (ADR 0021) i przez atrapę w testach; klient nie wie, którego używa

Osobne API dla klientów zdalnych (np. REST obok IPC)dwie powierzchnie do utrzymania i do przeglądu bezpieczeństwa; zasada planu: jeden protokół, trzy transporty
Zdarzenia bez numerów, klient po przerwie zawsze czyta cały standrogie na łączu komórkowym; nie rozwiązuje cichego gubienia paczek w trakcie odpowiedzi
Błędy jako tekstklient nie może ich tłumaczyć ani rozróżniać; trzy klienty powielałyby dopasowywanie napisów
ACL tylko w interfejsie (ukrywanie przycisków)zmodyfikowany klient wywoła wszystko; uprawnienia muszą być po stronie hosta
Typy TS dalej pisane ręcznieprzy trzech klientach rozjazd jest pewny; ADR 0013 już to rozstrzygnął
Protobuf / gRPCodrzucone już w ADR 0013 dla IPC; JSON jest czytelny i wystarczający, a przeglądarka i tak potrzebuje WebSocket

Konsekwencje

  • Zadania B.1 (generator typów), B.2 (seq i wznowienie w EventHub / pump.rs), B.3 (błędy strukturalne) i B.5 (local_only) nie dodają funkcji i mogą iść równolegle z etapem A; są warunkiem etapu D.
  • B.2 zamyka przy okazji otwarte ustalenie o deltach przychodzących w czasie wczytywania rozmowy.
  • Okno Tauri korzysta na zmianie od razu: przestaje po cichu gubić zdarzenia i dostaje kody błędów.
  • Lista poleceń local_only i ich zdalnych odpowiedników wymaga przeglądu wszystkich 210 poleceń; ścieżki bezwzględne w DTO to także kwestia prywatności (klient zdalny widzi układ dysku hosta) — do oceny przy B.5.
  • Test wymagany przed włączeniem dostępu zdalnego: zerwanie i wznowienie połączenia przy trwającej odpowiedzi — żadne zdarzenie nie ginie; klient bez uprawnienia do polecenia dostaje odmowę po stronie hosta.
  • Rozmiar bufora zdarzeń i limit rozmiaru ramki są budżetem zasobów modułu remote-gateway — progi ustala właściciel po pomiarach.

Jak cofnąć

  • Pola v i seq są dodatkiem: klient, który ich nie używa, działa jak dziś. Wyłączenie wznowienia sprowadza zachowanie do obecnego (pełne wczytanie stanu po przerwie).
  • Generator typów można wymienić (tauri-specta ↔ ts-rs) bez zmiany kontraktów — jak w ADR 0013.
  • ACL per klient przy jednym kliencie lokalnym z pełnym zestawem jest równoważna stanowi obecnemu.
