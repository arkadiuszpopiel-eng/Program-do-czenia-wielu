# scripts/

| Skrypt              | Co robi                                                                                                                 | Gdzie używany        |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `check-deps.sh`     | sprawdza przez `cargo metadata` + `jq`, że żaden crate `*-impl`/`*-fake` nie zależy od cudzego `*-impl` (tylko od `*-contract`; cudzy `*-fake` tylko w `dev-dependencies`); `--self-test` uruchamia wbudowany test reguł | CI (Linux), lokalnie |
| `pre-commit.sh`     | prettier, eslint, svelte-check, reguły Svelte 5, zakaz web fontów/backdrop-filter, aktualność tokenów                   | hook lokalny         |
| `check-svelte5.mjs` | wykrywa składnię Svelte 4 (`export let`, `$:`, `on:`)                                                                   | `pnpm lint`          |
| `check-css.mjs`     | wykrywa `@import url(` i `backdrop-filter` poza paletą poleceń                                                          | `pnpm lint`          |
| `setup-dev.ps1`     | Windows: sprawdza narzędzia do budowy Alfy; `-Install` (każdy krok za zgodą), `-Build`, `-Test` (także testy na żywym systemie, każdy za zgodą), `-Run`, `-Installer` — opis w `docs/user-guide/11-pierwszy-test-na-pc.md` | PC właściciela       |
| `install-on-drive.ps1` | Windows, świeży komputer: jedno polecenie instaluje wszystko na wskazanym dysku (`-Drive D`) — repozytorium `D:\alfa`, narzędzia `D:\alfa-narzedzia` (Rust, VS Build Tools, Git, Node.js, Perl, cache npm/pnpm; uprawnienia tylko właściciel/SYSTEM/Administratorzy), potem `setup-dev.ps1 -Build` i trzy skróty na Pulpicie (Alfa, aktualizacja kodu, praca nad kodem z Claude Code); `-Yes` bez pytań, `-Ci` tylko plan. Dane Alfy celowo zostają w `%LOCALAPPDATA%\Alfa` (ochrona Brokera po ścieżce) | PC właściciela, CI (`rehearsal.yml`, `-Ci`) |
| `update-dev.ps1`    | Windows: `git pull --ff-only` (bez nadpisywania lokalnych zmian) + `setup-dev.ps1 -Build`; skrót „Alfa — aktualizuj kod” | PC właściciela, CI (składnia) |
| `code-session.ps1`  | Windows: Claude Code (`claude`) w katalogu repozytorium — praca nad kodem przy działającej Alfie w trybie deweloperskim; skrót „Alfa — praca nad kodem (Claude Code)” | PC właściciela, CI (składnia) |
| `ci/hf-gguf-check.py` | modele GGUF z `providers-local-impl/models.toml` w API Hugging Face (bez pobierania): plik istnieje, rozmiar = `size_mb` (±1 MiB), przypięty `sha256` = hash LFS; tabela SHA-256 do przypięcia przez człowieka; `HF_ENDPOINT` — atrapa API w testach | CI (`rehearsal.yml`, job „Hugging Face”) |
| `gates.ps1`         | Windows: bramki jakości jednym poleceniem — format Rust partiami (`cargo fmt --all` przekracza limit długości linii poleceń), `check-deps.sh`, lint, svelte-check, vitest, odświeżenie `docs/CATALOG.md`; `-Test a,b` testy wskazanych crate'ów, `-Full` clippy, testy całego workspace'u i cargo-deny | PC właściciela, sesje AI |
| `portable-env.ps1` / `portable-env.sh` | Windows: środowisko z dysku przenośnego — w bieżącym oknie (PowerShell: `. .\scripts\portable-env.ps1`, Git Bash: `source scripts/portable-env.sh`) ustawia Rust, Node.js z pnpm, Strawberry Perl, cache npm i magazyn pnpm z katalogu `..\alfa-narzedzia`; niezależne od litery dysku, niczego nie zapisuje w systemie | PC właściciela, sesje AI |
| `catalog.mjs`       | generuje `docs/CATALOG.md`: wszystkie crate'y i moduły z grupą, falą, rodzajem, rozmiarem, liczbą testów i SPEC oraz lista niespójności (brak README, SPEC, `module.toml`, przekroczone limity rozmiaru) | lokalnie, `gates.ps1` |
| `docs-html.mjs`     | buduje `docs/html/` z planu v6, STATUS, KONTYNUACJA, dziennika zmian, ADR-ów i SPEC-ów nowych modułów: samodzielne strony HTML (styl z `docs-html.css`, fonty systemowe), strona główna z paskiem postępu etapów liczonym z `docs/plan/03-roadmapa.md`; `--check` buduje i kończy się błędem przy zerwanym odnośniku, brakującej kotwicy albo nieznanym stanie w roadmapie; `--verify` niczego nie zapisuje i kończy się błędem, gdy zatwierdzone `docs/html/` jest nieaktualne | po każdym etapie; `gates.ps1` i CI (`--verify`) |
| `memory-sync.sh`    | kopia pamięci projektu (`../memory`, pamięć asystenta, `../.remember`) do `docs/pamiec-projektu/`; dodaje nowe i aktualizuje zmienione pliki, **niczego nie usuwa** — plik, którego nie ma u źródła, zostaje i trafia na listę OSTRZEŻEŃ z gotowym poleceniem przywrócenia do źródła, a w takim (niepełnym) katalogu różniące się pliki nie są nadpisywane; `--prune` — lustro (usuwa z kopii i nadpisuje); odmawia przy czymś, co wygląda na klucz | koniec każdej sesji |
| `backup.sh`         | kopia bezpieczeństwa projektu na inny dysk: paczka git (wszystkie gałęzie), źródła bez `target`/`node_modules`/`.git`, `Alfa-uruchomiona`, pamięć, `SHA256SUMS.txt`, `ODTWORZENIE.md`; cel **tylko jawnie** (argument albo `ALFA_BACKUP_DIR`, bez domyślnego); przed zapisem sprawdza, że dysk istnieje i nie jest woluminem projektu (litera i numer seryjny), wypisuje etykietę i wolne miejsce, szacuje rozmiar i odmawia przy wolnym < 2 × szacunek; `--dry-run` — tylko sprawdzenia | na polecenie właściciela (Git Bash, Windows) |
| `tests/*.test.sh`   | testy skryptów bez bats (`lib.sh` — wspólne `check`/`run`): `memory-sync.test.sh` w piaskownicy w katalogu tymczasowym (Git Bash i Linux), `backup.test.sh` tylko z `--dry-run` i atrapami `robocopy`/`git`/`df` (Git Bash na Windows; przypadki z drugim dyskiem pomijane, gdy jest jeden dysk). Uruchomienie: `bash scripts/tests/memory-sync.test.sh && bash scripts/tests/backup.test.sh` | lokalnie po zmianie tych skryptów |
| `set-version.mjs`   | jedyny sposób zmiany numeru wersji: `node scripts/set-version.mjs 0.0.7` ustawia go w workspace Cargo, powłoce Tauri, interfejsie i manifestach modułów (`crates/*/module.toml`, których testy porównują wersję z crate'em); `--check` kończy się błędem przy rozjeździe albo braku wpisu w `CHANGELOG.md` | przy każdej nowej wersji; `gates.ps1`, CI |

Skrypty są częścią bramek jakości z §4.4 planu (`docs/PLAN.md`).

Narzędzia interfejsu (`apps/desktop/ui/scripts/`): `bundle-size.mjs` — budżet paczki JS/CSS (CI);
`shots.mjs` — zrzuty ekranu wszystkich widoków (rozmowa, panele, każda strona ustawień) w kilku rozmiarach okna,
do przeglądu układu i skalowania (`pnpm dev` w tle, potem `node scripts/shots.mjs <katalog> --sizes 1280x720,1920x1080`).
Testy E2E bez pobierania przeglądarki Playwrighta: `PW_CHANNEL=msedge pnpm test:e2e`; na laptopie z 16 GB RAM dodaj
`PW_WORKERS=4` (mniej przeglądarek naraz).
